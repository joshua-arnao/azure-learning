# FACTURACIÓN DE GITHUB

---
## FACTURACIÓN EN GITHUB
GitHub factura cuentas basadas según su tipo, ya sea: *personal*, *organización* o *empresa*.

Las cuentas *personales* y la mayoría de las *organizaciones* **reciben facturas independientes**.

Las cuentas *empresariales* pueden **consolidar la facturación en varias organizaciones** o **enrutar los cargos a diferentes centros de costos** en función de la configuración interna.

Cada factura puede reflejar una combinación de **cargos de licencia basados en suscripciones** y **cargos basados en el uso**:

- **Los cargos de suscripción y licencia** se aplican a productos y servicios asignados a una cuenta, como *GitHub Pro*, *GitHub Team* o puestos de *GitHub Copilot*. 
- **La facturación basada en el uso** se aplica a los productos en los que los costos se pueden escalar con el consumo, como *Acciones de GitHub*, *paquetes de GitHub* y *características de GitHub Copilot admitidas*.

## FACTURACIÓN GITHUB COPILOT
GitHub Copilot usa una combinación de **facturación basada en licencias** y **facturación basada en el uso**.

Las organizaciones y las empresas se facturan por las licencias de GitHub Copilot asignadas a los usuarios. Se pueden agregar más puestos Copilot durante un ciclo de facturación y se prorratean durante el período en el que se asignan. La eliminación de un puesto generalmente afecta a la facturación en el siguiente ciclo de facturación.

Una licencia de Copilot asignada no debe tratarse como equivalente a un usuario activo. Un usuario puede tener asignada una licencia de Copilot facturable aunque no haya usado recientemente Copilot.

## PRECIOS POR GITHUB ACTIONS
GitHub Actions permite automatizar los flujos de trabajo directamente dentro de repositorios. Su modelo ed precios varía en función de la **visibilidad del repositorio** y el **tipo de cuenta**:

-  **Repositorios públicos**: el uso de GitHub Actions es **gratuito** para repositorios públicos, lo que proporciona minutos ilimitados en GitHub-hosted runners
- **Repositorios privados**: cada cuenta recibe algunos minutos gratuitos y almacenamiento para los GitHub-hosted runners, en función del plan de la cuenta.

## PRECIOS Y OPCIONES DE SOPORTE TÉCNICO PARA ORGANIZACIONES
GitHub ofrece varios planes adaptados a las necesidades de la organización, cada uno con características distintas:
- **Características gratuitas de GitHub para organizaciones**:
  - Repositorios públicos o privados ilimitados
  - Apoyo comunitario
  - 2000 minutos de CI/CD al mes
-  **Características del equipo de Github**:
  - Todo en Gratis, además de:
    - Más herramientas de colaboración.
    - Propietarios de código.
    - Revisiones necesarias.
    - Protecciones de rama aplicadas.
    - Soporte técnico por correo
- **Características de GitHub Enterprise**:
  - Todo en team, además de:
    - Inicio de sesión único de SAML (Lenguaje de marcado para confirmaciones de seguridad)
    - Auditoría avanzada
    - GitHub Connet
    - Soporte técnico 24/7
    - Características de seguridad de nivel empresarial.

## FUNCIONALIDADES DE LA PLATAFORMA DE FACTURACIÓN
- **Controles de gasto pormenorizados**: Los administradores pueden establecer límites de gasto para los servicios basados en uso admitidos, lo que ayuda evitar un uso excesivo inesperado.
- **Información detallada sobre facturación y uso**: las vistas de facturación proporcionan visibilidad de los puestos asignados, los costos de licencia, el consumo de crédito de IA y los gastos. 
- **Informes automatizados**: la información de uso y facturación puede admitir la supervisión financiera y los contracargos internos.


## COPILOT PANELES DE USO E IMPACTO
GitHub proporciona paneles independientes para comprender cómo los usuarios adoptan e interactuán con Copiloto. Estos paneles **no son informes de facturación**.

- **Panel de métricas de uso Copilot**: Informa de la telemetría de adopción y participación, lo que ayuda a los administradores a comprender como se usa Copilot en la organización o empresa.
- **Panel de impacto Copilot**: Proporciona otra vista de la adopción mediante la agrupación de usuarios en cohortes de adopción, incluido un segmento pasivo. Estos cohortes de adopción se basan en la actividad de un usuario en una ventana gradual de 28 días.
